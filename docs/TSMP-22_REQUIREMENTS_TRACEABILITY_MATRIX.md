# TSMP-22 (MLE-22) - Requirements traceability matrix

Requirement → architecture → design → source code → unit test → integration test → system test
→ validation result, for FR-001..027, SEC-001..010 and NFR-001..011.

**Sources.** Requirements, priorities and verification methods come from SRS Part A, Sections
5-6. Architecture references (ARCH-*) come from SAD 2.2, design references from SAD 4-7
(API-nn, classes, D-nn decisions) and test IDs from STP Part C, Section 9. Source paths are the
actual files on `feature/TSMP-21-22-validation`. The STP RTM's planned paths (for example
`accounts/history.py`, `benchmarking/exporters.py`) were replaced by the real ones.

**Test notation.** `file::test` is a pytest test in `tests/`. Parametrized tests are named
without their ids. `SYS:<ID>` is a case in `scripts/validation/system_tests.py`, run against the
Docker Compose stack (results in `docs/evidence/tsmp-21/system-results.json`). `UI:<ID>` is a
case in `scripts/validation/browser/results_dashboard.mjs`, run in Chrome against the stack
(results in `docs/evidence/tsmp-21/browser-results.json`, screenshots in
`docs/evidence/tsmp-21/screenshots/`). `DOCKER:` tests run in `tests/test_sandbox_docker.py` on a
Linux Docker host.

**Status rule.** A requirement is **VERIFIED** when every verification method named for it in
the SRS has passed. It is **PARTIAL** when some evidence passes but a required method fails or is
blocked, **NOT VERIFIED** when no required method could be executed, and **NOT IMPLEMENTED** when
the function does not exist. Open defects are listed next to the status. Full test results are
in [TSMP-21_TEST_EXECUTION_REPORT.md](TSMP-21_TEST_EXECUTION_REPORT.md).
